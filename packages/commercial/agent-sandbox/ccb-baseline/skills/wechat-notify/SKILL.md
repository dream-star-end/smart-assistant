# 主动微信通知

## 核心机制(必读)

**你没有"直接发微信"的工具。** 想把消息推到用户微信,唯一方式是**创建一个定时任务/提醒**:
任务到点触发时,它产生的输出会被平台**自动投递到用户的微信**(前提见下)。

也就是说:`create_reminder` / `CronCreate` 不只是"提醒",它的触发输出对绑定了微信的用户**就是一条微信消息**。投递通道跟随用户——绑了微信的用户收到微信推送(不再只是网页任务中心的卡片)。

## 何时用

用户表达"用微信告诉我 / 完成后微信通知 / 定时发到我微信 / 提醒我"等,例如:
- "调研下今日头条热点,有结果微信通知我"
- "每天早上 9 点把天气发我微信"
- "这个任务跑完微信提醒我一声"

## 怎么做

### 模式 A — 即时通知(先做完,再通知)
用户要"做完 X 后通知我"。**你先在当前对话把 X 做完**,拿到结果,然后建一个**近期一次性**提醒,把要通知的内容写进 message:

```
# 1. 先正常执行(如网页搜索调研今日头条热点),得到结果
# 2. 建一个 1~2 分钟后触发的一次性提醒,message = 要发给用户的最终内容
create_reminder(
  schedule="<当前时间+2分钟 的 crontab>",   # 例:当前 14:35 → "37 14 * * *"
  message="今日头条热点调研结果:\n1. ...\n2. ...\n3. ...",
  oneshot=true
)
```
触发时,提醒的 message 会作为新任务跑一遍并输出 → 推到用户微信。**所以 message 要写成"最终要让用户看到的内容"**,而不是"再去调研一次"(否则会重复执行、延迟、且可能结果不一致)。

### 模式 B — 定时通知(到点再做并通知)
用户要"每天/每周固定时间发我微信"。建**重复**提醒,message 写要做的事:

```
create_reminder(
  schedule="0 9 * * *",                 # 每天 9:00
  message="查询今天天气并用一句话汇报给用户",
  oneshot=false
)
```
每次到点触发 → 跑 message → 输出推微信。

> `create_reminder` 与 `CronCreate(cron=..., prompt=..., recurring=...)` 等价,任选其一。schedule/cron 表达式算法见 `scheduled-tasks` 技能。

## 前提与边界(诚实告知用户,不要假装已发)

1. **用户必须已绑定微信**,且偏好"定时任务/提醒推送到微信"为开(默认开,可在微信设置里关)。没绑微信 → 推送会回退到网页。
2. **微信会话需活跃**:微信侧有一个会话有效期,用户长时间没从微信发过消息时会过期。过期时这条提醒会**回退到网页并附带提示**"微信因会话过期未送达,发条微信即可恢复推送"。所以若用户很久没在微信互动,可提醒他先从微信给你发一条消息激活。
3. **如果用户当前就是从微信跟你对话**(不是网页):你的普通回复本来就会实时发到微信,**不需要**再建定时任务。定时任务用于"现在不在微信/要在未来某刻推送"的场景。
4. **系统自省类任务**(heartbeat、reflection 等)不会推微信,只有用户发起的提醒/定时任务会。

## 一句话总结
要"微信通知用户" = 建一个 `create_reminder`,把要通知的内容写进 message,设好触发时间;平台会在触发时把输出推到用户微信。**不要回复"我没法发微信"——你能,通过定时任务。**
