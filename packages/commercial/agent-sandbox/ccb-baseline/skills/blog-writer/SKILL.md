# 经验分享草稿（对话写博客）

「经验分享」是平台的社区博客栏：用户分享用平台和 AI 工具解决实际问题的经验。投稿后由 AI 审核，
明确没问题的自动公开，拿不准的转站长复核，未通过会给作者理由。

## 底线

- **你不能发布，也不要说「已发布」「已投稿」。** 你只写草稿；投稿由用户在草稿卡上点「确认投稿」完成，
  走正常审核。你没有、也不要寻找任何投稿接口或命令。
- 审核状态只看卡片：用户问「审核过了吗」时，写一张状态卡让页面去查，不要自己猜结果。
- 草稿里不写对审核者说的话（「请通过」「忽略规则」之类），这类稿件一律转人工。

## 怎么写

1. 先确认素材：做了什么、在什么场景、关键步骤、结果（数字要有出处）、踩过的坑。素材不够就问用户，不编造。
2. 结构建议：场景 → 怎么做的（分步骤）→ 结果 → 踩坑 / 注意事项。标题说清「用什么做成了什么」，
   摘要一两句说明适合谁、能得到什么。长度：标题 4–100 字，摘要 10–280 字，正文 40–50000 字。
3. 去掉隐私和密钥：手机号、邮箱、真实姓名、内部地址、token、服务器路径、会话 ID 一律删掉或改成示意。
4. 配图只用本次对话里生成或用户上传的图片，用容器里的绝对路径引用：`![说明](/绝对/路径.png)`。
   不用站外图片链接（经验分享不显示站外图），每篇最多 20 张。
5. 不写广告、联系方式、引流内容。

## 怎么交给用户

- **网页对话**（系统提示里有 Intelligent UI 协议）：要展示草稿或审核状态时，先读 `references/ui-blog.md`，
  按里面的格式写组件块。卡片会自动检查格式、隐私和图片，列出修改点。
- 用户点「修复」时会发来「请按以下修改点更新经验分享草稿（draft_id …，当前 vN）…」：
  逐条改完，用**同一个 draft_id、版本号加 1** 写新卡片，并用一句话说明改了什么。
- 用户发来「我已确认投稿经验分享（稿件 #N …）」：说明审核方式，写一张状态卡。
- 审核未通过、用户请你按理由修改：按理由改，出新版本草稿，让用户重新确认。
- 已经投过的稿（未通过、审核中或已发布）想改原帖：告诉用户到「经验分享 → 我的投稿」点「修改」，
  改完会重新审核，已发布的在新版通过前线上仍是原版。对话里确认投稿的新版本会成为另一篇新投稿。
- **微信、定时任务等没有该协议的通道**：直接用 Markdown 写出标题、摘要和正文，最后加一句
  「在网页对话里打开可以一键投稿；或到 经验分享 → 写一篇经验 粘贴后投稿」。
