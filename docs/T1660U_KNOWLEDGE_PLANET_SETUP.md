# t1660u：知识星球授权失败收尾

DO NOT MERGE — 发版前问用户。本变更仅提交商业版草稿 PR，未合并、未发布、未操作生产。

## 证据及限制

2026-11-08 用户 4 的两次 setup 创建返回 201，随后状态轮询返回 200，约 50 秒结束；没有请求二维码图片。扫码容器直至约四分钟总期限才退出，其间创建返回 CAPACITY_EXCEEDED。复制的 setup/HTTP 源码与本次基线相同。现有日志没有 worker 失败阶段，不能据约 50 秒耗时断言 45 秒捕获上限就是根因。

开发环境使用空浏览器上下文、现有 origin 白名单与现有 captureQr 实现访问公开登录页面：按钮、同意覆盖层、微信 iframe 均出现，约 2.69 秒取得通过原有像素校验的 PNG；没有保存/展示二维码、扫码或使用账户凭据。该探测不是生产 Docker/网络/代理环境，不能排除线上代理、上游页面或图片加载问题，也不能证明真实用户授权已恢复。

已证实的代码缺陷是失败收尾：setup 的 failed 回调只改变展示状态，没有停止 worker；worker 通用失败仅写帧，不执行成功分支已有的 flush-and-exit，而且登录异常先等待 browser/relay 清理，可能卡住。失败可因此占用容量到总期限。回归测试以真实子进程、永不返回的 browser.close、保持存活的句柄复现失败退出问题；模拟 Docker 验证失败帧触发精确容器停止与名额释放。

## 修改

- 登录失败/超时通过既有 writeTerminalAndExit 刷新终态帧并退出，交父服务清理容器及 broker。正常扫码仍以 authenticatedProbe 为认证权威，不改变二维码像素校验、45 秒预算、网络白名单或容量。
- failed 帧在父服务立即停止本 invocation 的容器。setup 在失败/取消/过期时幂等停止，并处理回调先于 handle 返回的窗口；旧 handle 无法停止复用同一 key 的新 worker。最终账号仍须等待 worker 清理成功才保存。
- setup 增加不依赖前端轮询的到期回收；未取得二维码的总期限耗尽展示生成超时。异步 done 异常也封住迟到认证。
- 诊断仅包含 sessionId、固定阶段、固定错误枚举；worker 帧解析严格拒绝额外字段及自由文本。网络错误归类为 DNS、连接、TLS、代理、HTTP 等；不输出 URL、查询参数、错误原文、二维码、Cookie、storageState 或凭据。reason 是观测到的失败类别，不等于已确认生产根因。
- 知识星球前端区分二维码生成失败/超时与扫码名额已满；终态停止轮询和图片请求、回收 blob，忽略迟到结果，支持重试。创建中关闭弹窗后，迟到的等待扫码会话会被取消。
