# OpenClaude v5 商业版 UX 审计（2026-07-16）

## 结论

本次以真实用户完成任务的路径为主线，覆盖聊天主界面、Composer、320–768px 窄屏、账户与计费、AI 市场、管理中心、组织中心、站内信及管理后台。证据全部使用最终代码的组件行号；本 worktree 没有浏览器自动化/截图链路，因此未用截图代替代码证据。

共登记 **42 项**：**P0 4 / P1 29 / P2 9**。截至第三轮累计修复 **34 项**（P0 3 / P1 23 / P2 8）：#68 修复 12 项、#72 修复 19 项、本批修复 3 项。余下 **8 项**继续登记交接，包含 Composer 并行区、跨层错误信封和需要产品决策的改动。

优先级口径：P0 = 直接造成错误认知、核心任务不可完成或明显体验伤害；P1 = 可绕过但持续制造摩擦；P2 = 一致性、可发现性或精细度打磨。

## 已验证的现有保护

- 消息流统一由 `MessageList` 控制 `gap-4`、最大正文宽度与移动端边距，助手正文和用户气泡均有 `break-words`；见 `packages/web-react/src/components/MessageRenderer.tsx:396`、`packages/web-react/src/components/chat/cards.tsx:274`。
- 长代码、长表格与长公式均在自身区域横向滚动；表格滚动区现可键盘聚焦并带窄屏提示；见 `packages/web-react/src/components/CodeBlock.tsx`、`packages/web-react/src/components/MarkdownImpl.tsx`、`packages/web-react/src/styles.css`。
- 助手图片已有渐进加载、失败重试、点击放大、打开时重签名和编辑入口；全屏查看器底部使用 safe-area；见 `packages/web-react/src/components/chat/media.tsx:258`、`packages/web-react/src/components/ImageViewer.tsx:587`。
- Tool、Thinking、Agent/Delegate 卡片都使用同一套 surface/border/status token，流式默认展开、完成默认折叠的主规则一致；见 `packages/web-react/src/components/ToolCard.tsx:60`、`packages/web-react/src/components/chat/cards.tsx:436`、`packages/web-react/src/components/chat/AgentGroupCard.tsx:58`。
- 站内信首屏已有 skeleton、加载失败重试、未读/全部两种诚实空态；见 `packages/web-react/src/components/InboxDialog.tsx:297`。
- 旧 `_emptyTurnTimeout` 文案已明确说明“连接中断、内容可能已在服务端生成”，没有继续误导为“模型无响应”；见 `packages/web-react/src/components/chat/cards.tsx:364`。
