### CG2 — sessionsDb.ts 修 2 个 TS2352(storage own-errors 2 of 14 修)

**文件**:`packages/storage/src/sessionsDb.ts` 行 1037 / 1040

**降级修法**(按顺序试,采用第一个 TS 接受的最小写法):

#### 试 1:不带任何断言

```ts
out[i] = { ...m, _seq: old._seq }    // 1037
out[i] = { ...m, _seq: nextSeq }     // 1040
```

**期望**:`m: T & {_seq?: number}`,spread 后 `T & {_seq?: number} & {_seq: number}` 与 T 无明确类型关系,**TS 大概率仍要求 cast**(因为 T 被擦成 `T extends ... ? unknown : ...` 这类无 indexer 的形态)。

#### 试 2:`as T`(普通断言)

```ts
out[i] = { ...m, _seq: old._seq } as T
out[i] = { ...m, _seq: nextSeq } as T
```

**期望**:与 v1 plan 中错误消息描述一致,TS 还是会报 `not sufficiently overlap` 因为 spread `...(m as object)` 已经把命名属性擦掉。但**先把 `(m as object)` 去掉直接 spread `m`**,新 spread 类型可能更接近 T,有机会过。

#### 试 3:`as unknown as T`(双断言)

```ts
out[i] = { ...m, _seq: old._seq } as unknown as T
out[i] = { ...m, _seq: nextSeq } as unknown as T
```

**保底方案**,运行时不变。

#### 试 4(若前 3 都不雅):重写为不通过 spread

```ts
const next: T = m as T
;(next as { _seq: number })._seq = old._seq    // 但这变异原对象 — 不能用 except if cloning
```

→ 不推荐,会引入运行时副作用。**到试 3 必停**。

**实施时**先跑试 1 看实际报错,再决定;每一档失败都记录到本文档 §3.5(实测降级表)。**不要**立即降到双断言。

**验收**:
- `npx tsc --noEmit -p packages/storage/tsconfig.json` 0 errors
- runtime 行为不变(seqOrder 测试若有,跑过)

### CG3 — gateway test 3 个错(gateway own-errors 3 of 3 修)

**文件**:`packages/gateway/src/__tests__/codexAppServerRunner.test.ts` 行 1034-1036

```ts
// 修前
assert.equal(err.rpcCode, -32600)
assert.equal(err.rpcMessage, 'no rollout found for thread id xyz')
```

#### CG4.3 `runtimeEntrypointPolicy.test.ts:24`(TS5097 + 仓外 TS 静态 import)

**当前问题**(实测):
```ts
import { isProviderManagedEnvVar } from "../../../../claude-code-best/src/utils/managedEnvConstants.ts";
```
有两个独立问题:
1. `.ts` 后缀 → TS5097
2. **静态 import 了 commercial 包 include 之外的源文件**(仓内同 monorepo,但 `claude-code-best/` 不在 `packages/commercial/src` 之下)

**v2 计划**只修问题 1(去后缀),**v3 修法重做**:在 composite 模式下,问题 2 才是真坑 — 任何被静态 import 的 .ts 文件都会被 commercial composite project 纳入编译图,触发 rootDir 错误或破坏 references 拓扑。**简单去 `.ts` 后缀解决不了**。

**主修法**(优先此):**改成读源码字符串解析,不再静态 import**

测试文件已经在用 `readFileSync(ENTRYPOINT_TS_PATH)` + 正则解析 `entrypoint.ts` 的源码(见 `readRetainKeysFromSource()` line 38-50),**完全可以同样方式处理 `managedEnvConstants.ts`**:

```ts
// 删除 line 24 的 import
- import { isProviderManagedEnvVar } from "../../../../claude-code-best/src/utils/managedEnvConstants.ts";

// 加一个本地实现 — 从源码读 PROVIDER_MANAGED_ENV_VARS Set + 前缀
const MANAGED_ENV_CONSTANTS_PATH = join(
  __dirname, "..", "..", "..", "..", "claude-code-best", "src", "utils", "managedEnvConstants.ts"
);
function loadManagedEnvVarsFromSource(): { exact: Set<string>; prefixes: string[] } {
  const src = readFileSync(MANAGED_ENV_CONSTANTS_PATH, "utf-8");
  const setMatch = src.match(/PROVIDER_MANAGED_ENV_VARS\s*=\s*new Set\(\[([\s\S]*?)\]\)/);
  if (!setMatch) throw new Error("PROVIDER_MANAGED_ENV_VARS not found");
  const exact = new Set<string>();
  for (const lit of setMatch[1]!.matchAll(/'([A-Z0-9_]+)'/g)) exact.add(lit[1]!);
  // 提取已知 startsWith 前缀(VERTEX_REGION_CLAUDE_ 等),正则匹配源码模式
  const prefixes: string[] = [];
  for (const lit of src.matchAll(/key\.startsWith\(['"]([A-Z0-9_]+)['"]\)/g)) prefixes.push(lit[1]!);
  return { exact, prefixes };
}
function isProviderManagedEnvVar(key: string): boolean {
  const { exact, prefixes } = loadManagedEnvVarsFromSource();   // 实施时缓存到 module-level 一次
  return exact.has(key) || prefixes.some(p => key.startsWith(p));
}
```

(实施时把 `loadManagedEnvVarsFromSource()` 调用放 describe 上方一次缓存,不要每个 assert 都 readFileSync。)

**理由**:
- 测试本就声明自己是"读源码当策略声明文件"的测,不需要真跑被测代码 → 本身就该用 readFileSync 不 import
- 完全切断 commercial composite project 与 claude-code-best 源码的编译期耦合
- runtime 行为不变(测试还是验证 personal-version managedEnvConstants.ts 的语义稳定)
- **不用** `allowImportingTsExtensions`(那只是把"composite 边界" 这个下个问题暴露出来)
- **不用** dynamic import(也会让 TS 试着解析,且比 readFileSync 复杂)

**风险**:
- 解析正则若与 personal-version 源码漂移(例如 someone 改成 `Set([...])` 不带 new)→ 测试 fail,提醒同步
- 这个失败模式是**好的**,正是测试目标(声明同步)

**判断**:实施时直接照做。这个修法明显优于 v2 误判的"去 .ts 后缀"。

**验收**:
- `npx tsc --noEmit -p packages/commercial/tsconfig.json` 测试错误清零,只剩 src 4 个

#### CG5.2 `computeHostsDiskMonitor.ts:189`(TS2339 `never.toString`)

```ts
// 当前(line 189 column 75)
return { stdout: typeof r.stdout === "string" ? r.stdout : r.stdout.toString("utf8") }
```

`r.stdout` 类型推断坍塌 `never` 是因为 child_process exec 重载在新 @types/node 已把 stdout 声明为 `string`(default util.promisify form),else 分支不可达 → never。

**主修法**(优先此):

```ts
return { stdout: String(r.stdout ?? '') }
```

**理由**:
- 最小、无 cast、无尴尬的 `as Buffer` 让人误以为 runtime 真有 Buffer 路径
- string 输入 String() 是恒等,语义一致
- nullish 兜底(?? '')虽然 TS 推断已经是 string 不会 null,但明确写出来表达意图

**降级**(若 `String()` 触发 lint 警告):
```ts
return { stdout: r.stdout }   // 直接返,因为 TS 已经推断它是 string
```

**不采用**:`(r.stdout as Buffer).toString("utf8")` — 这个 cast 不真实(runtime 不会进 else 分支)。

#### CG5.3 `tunnelHttpReader.ts:306,489`(TS2339 `Duplex.setTimeout`)

`Duplex` 上没有 `setTimeout`,但 `net.Socket` / `tls.TLSSocket` 有(它们 extends Duplex)。

**主修法**(优先此 — 收紧类型):

```ts
// 修前
import type { Duplex, Writable } from "node:stream";
// 函数签名:socket: Duplex

// 修后
import type { Writable } from "node:stream";
import type { Socket } from "node:net";
// 函数签名:socket: Socket
// (若发现某些 callsite 传 TLSSocket,union: Socket | TLSSocket;实测 TLSSocket extends Socket 不需要 union)
```

**理由**:从代码注释看 tunnel HTTP socket 是 net 层 socket,实际 callsite 传的就是 net.Socket。把类型从 Duplex 收紧到 Socket 是真实情况的反映,setTimeout 等 socket-only 方法自然可用。

**降级**(若发现 callsite 真传 Duplex):
```ts
;(socket as Socket).setTimeout?.(idleTimeoutMs, () => finishErr('idle_timeout'))
```

**判断**:Codex 二审确认 "tunnel TLS socket 语义" — 收紧到 Socket 方向对。实施时 grep 7 个 `socket: Duplex` 函数 callsite 确认。

#### CG5.4 `tunnelHttpReader.ts:486,494`(TS2322 `Buffer<ArrayBufferLike>`)

@types/node 较新版本 Buffer 携带 ArrayBuffer 泛型参数。`Buffer.concat([buf, chunk])` 返回 `Buffer<ArrayBufferLike>`,赋给 `Buffer<ArrayBuffer>`(默认参数)报错。

**主修法**(优先此 — 改 buf 声明):

```ts
// 修前(隐式 buf 类型 = Buffer<ArrayBuffer>)
let buf: Buffer = ...

// 修后
let buf: Buffer<ArrayBufferLike> = ...
```

**理由**:Buffer.concat 真返回 ArrayBufferLike(更宽松),改声明对类型链更真实。如果传播面变大(例如 buf 后续用作其他 API 入参,期望具体 ArrayBuffer),失败再退回局部 cast。

**降级**(若 buf 声明改了导致下游报错):

```ts
// 局部 cast,保留具体 Buffer 类型
buf = buf.length === 0 ? chunk : (Buffer.concat([buf, chunk]) as Buffer)
```

**判断**:Codex 二审 NIT 4 确认改声明优先。实施时看 buf 在该函数内部用法,若只在本函数闭包里用,改声明无外溢风险。

**验收**:
