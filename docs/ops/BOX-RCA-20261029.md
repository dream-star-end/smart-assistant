## 2. 校验链与本次变更

1. `proxy/index.ts` / `boxPreparedContinuation.ts` 在入场分类 fresh / continuation_candidate / reject。`normalizeBoxSemanticBody` 先处理缓存、Skill 正文、图片说明和预算尾；任意尾随用户文本不静默归到某个工具，而走已有 answered-exchange restage。新请求附件仍要满足可发布契约。
2. `boxDurableJournal.ts::claimToolResume` 检查 uid/session/turn、authority、唯一 owner、lease/CAS、catalog/context/hash，随后 `boxToolResultMatcher.ts` 用 tool_use_id 配对结果。缺失/重复/外来 ID、输入或历史内容被改写仍拒绝。现有 assistant 历史顺序校验不变；发布结果哈希和计费语义不变。
3. `boxToolResultEcho.ts` 原来先严格限定内容形状，再比较 JSON SHA256，遇到 CLI 版本改变包装即可能误拒；旧代码通过空结果标记、持久化预览、图片来源等逐项白名单补洞。
4. 新 `boxResultSemantics.ts` 集中投影已发布结果的 CLI 观察值：string/text 数组与相邻文本拆分归一；文本不 trim、图片比较原字节和 MIME；只递归 `content` 包装，限制块数、深度、访问数，避免把任意 payload 字段当身份或结果。按已知语义判 equivalent / incompatible / unknown_shape。未知附加字段或包装不再单独导致拒绝；完全不透明的新类型在 ID、错误态已绑定且已发布内容在手时继续并告警。已知内容矛盾始终拒绝；已知有损预览仍要完成原证明。只有 hash、没有已发布内容的恢复路径保持严格校验。
5. 此策略接入共用 echo 验证器，因此在线 continuation、terminal recovery、unknown observer 共用。不会让未完成的后台通知伪装成工具完成。新请求中音频、语义 citations、非法 document 等原拒绝仍保留：它们是实际将要发布的新内容，缺乏一个既有已发布结果作为语义锚点。未知形状默认继续的承诺限于有该锚点的 CLI 回显；本 PR 没有让所有未知请求模态自动可发布。
6. `boxContinuationMetrics.ts` 提供固定枚举 stage/reason 的 warning 与 counter，不记录内容、ID、未知字段值。admission 拒绝、最终未恢复的 journal claim 拒绝、echo 拒绝分别记数；兼容告警记 envelope / opaque_content。已恢复的 orphan 不计 claim 拒绝。原有日志保留。

其它不稳定源：占位释放曾在传输层本地拒绝 256 字节探测上限而根本没发请求（#1180）；not_accepted 主要是旧 Box run 未收尾造成网关 `IDLE_HISTORY_PENDING`，不等于模型已执行失败；journal 依赖可验证终态/清理证明，断流、目标不可达和未确认发布会留下 unknown/占位，不能靠放宽结果形状清掉这些状态。

## 4. grok-rf-metrics SQL 契约

以下窗口可替换成统一指标参数；首次复算固定使用研究窗口，避免滚动时间或人用/自动恢复口径混淆。`not_accepted` 是 outcome；NULL outcome 计入非 completed，同时单列未终态。用 `COUNT FILTER` 而非排除 NULL。

```sql
BEGIN READ ONLY;
WITH human_box AS (
  SELECT *, CASE WHEN model LIKE 'box-api-claude%' THEN 'box-api-claude'
                 WHEN model LIKE 'box-claude%' THEN 'box-claude'
                 ELSE 'box-other' END AS family
  FROM turn_dispatches
  WHERE user_id=3 AND session_id LIKE 'web%'
    AND client_message_id LIKE 'm-%' AND client_message_id NOT LIKE 'm-recover-%'
    AND model LIKE 'box-%'
    AND admitted_at >= timestamptz '2026-09-29 00:00+08'
    AND admitted_at < timestamptz '2026-10-30 00:00+08'
)
SELECT family, count(*) AS total,
       count(*) FILTER (WHERE outcome='completed') AS completed,
       count(*) FILTER (WHERE outcome IS DISTINCT FROM 'completed') AS non_completed,
       round(100.0*count(*) FILTER (WHERE outcome IS DISTINCT FROM 'completed')/nullif(count(*),0),2) AS non_completed_pct,
       count(*) FILTER (WHERE outcome='not_accepted') AS not_accepted,
       count(*) FILTER (WHERE status IS DISTINCT FROM 'terminal') AS non_terminal
FROM human_box GROUP BY family ORDER BY family;
ROLLBACK;
```

17:28Z 复核（滚动最近30天，该样本与研究期 Box 样本一致）：box-api-claude 42 / completed34 / non_completed8（19.05%）/ not_accepted5；box-claude 16 / 11 / 5（31.25%）/5；box-other 6/6/0/0。**研究的14个 Box not_accepted 是 H+S；H 只有10个**。

```sql
BEGIN READ ONLY;
SELECT model, coalesce(failure_code,'unknown') AS reason, count(*) AS not_accepted
FROM turn_dispatches
WHERE user_id=3 AND session_id LIKE 'web%' AND model LIKE 'box-%'
  AND outcome='not_accepted'
  AND admitted_at >= timestamptz '2026-09-29 00:00+08'
  AND admitted_at < timestamptz '2026-10-30 00:00+08'
GROUP BY model, coalesce(failure_code,'unknown') ORDER BY not_accepted DESC;
ROLLBACK;
```

H+S 复核：box-api opus9、box haiku4、box sonnet1，共14。不要把恢复或委派回调计入 H。

### 续接拒绝（新增可持久化指标）

进程 counter：`box_continuation_rejected_total{stage,reason}` 与 `box_continuation_shape_compatible_total{stage,reason}`。通过既有 `observeDurableHistogram` 以 value=1、空边界记入 `telemetry_metric_rollups`；metric=`box_continuation_decisions`，labels.kind=`<admission|claim|echo>:<rejected|compatible>:<reason>`。不改 schema。汇总 **sample_count**，不是 counter_value；既有机制按 process_run_id/五分钟桶 upsert 绝对快照，不能把同一桶历次抓取结果相加。最多约一分钟刷盘延迟，进程崩溃/桶淘汰可能丢样本，须检查既有 dropped/flush 告警。SQL 是全个人实例的校验事件数，不是去重 dispatch 数；一个回合重试可能多次拒绝，echo 恢复观察也可重复。未知原因落 `other`，不能加入用户可控高基数标签。

```sql
BEGIN READ ONLY;
SELECT bucket_start,
       split_part(labels->>'kind',':',1) AS stage,
       split_part(labels->>'kind',':',2) AS decision,
       split_part(labels->>'kind',':',3) AS reason,
       sum(sample_count) AS decisions
FROM telemetry_metric_rollups
WHERE metric='box_continuation_decisions'
  AND bucket_start >= now()-interval '30 days'
GROUP BY bucket_start, labels->>'kind'
ORDER BY bucket_start, stage, decision, reason;
ROLLBACK;
```

只看拒绝可加 `AND split_part(labels->>'kind',':',2)='rejected'`。允许 stage 分开展示，不把 claim 所有基础设施失败统称形状拒绝。当前接线覆盖入场分类拒绝、最终未恢复的 journal/decision claim 错误、echo 错误；transport 超时、未证明发布等不是本指标，仍看原 journal/日志。本 PR 尚未部署，旧窗口没有此 metric 应展示“未采集”，不能显示“拒绝=0”。旧 `request_finalize_journal` 不覆盖准入前 409，不能拿它替代完整拒绝次数；日志里的 `proxy_box_continuation_rejected` 只能给留存窗口的观测下界，不与新增事件直接相加。
