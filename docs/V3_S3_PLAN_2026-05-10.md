## 3. 共享 helper 处理(grep-driven,**不预先抽象**)

**策略**: 每个 helper 先 `grep` 看 caller 数,再决定:
- **caller ≥ 2 跨资源** → `http/admin/_shared.ts`
- **caller = 1** → 跟 handler 走 module-private(直接搬到对应资源文件)
- **caller ≥ 2 但都在同 1 资源** → 该资源文件内 module-private export

### 3.1 已知确定要进 _shared.ts(纯 HTTP 解析)
- `extractTailId` / `extractTailSlug`
- `parsePositiveInt` / `parseNonNegativeInt` / `parseUserId` / `parseBigintIdParam` / `parseIsoTimestamp`
- `translateRangeError`

### 3.2 已知确定 module-private(单资源)
- `serializeUser/UserDetail/UserWithStats` → `users.ts`
- `USER_DETAIL_RE` 常量 → `users.ts` module-private
- `handleAccountRecentUsers` 是 accounts 域内私有函数(被 handleAdminGetAccount dispatch 调用) → `accounts.ts` module-private
- `HOST_UUID_RE` → `containers.ts` module-private(只在 listAgentContainers/Logs/Action 用)
- `ORDERS_MAX_LIMIT` / `BIGINT_MAX` → `orders.ts` module-private
- `FEEDBACK_MAX_LIMIT` → `feedback.ts` module-private
- `serializePlan` → `plans.ts`
- `serializePricing` → `pricing.ts`
- `serializeAudit` → `audit.ts`
- `serializeSetting` / `extractTailKey` → `settings.ts`
- `serializeOrderRow/OrderDetail/OrdersKpi` / `parseOrderStatus` → `orders.ts`
- `serializeFeedbackRow` / `parseFeedbackStatus` → `feedback.ts`
- `serializeAdminInboxMessage` / `inboxAuditSnapshot` → `inbox.ts`
- `serializeEgressProxy` → `egressProxies.ts`
- `serializeLedger` → `ledger.ts`(单 caller 在 ListLedger handler)
- `parseLedgerFilter` → **`ledger.ts` export**,`export.ts` 从 ledger.ts import(跨 ListLedger + ExportLedgerCsv,blocker #4 修复)
- `serializeAccount` / `fetchEgressProxyLabels` → `accounts.ts`
- `parseContainerActionUrl` → `containers.ts`
- `matchUserModelGrantsList` → **`modelGrants.ts` export**(被 `users.ts` 内部 dispatch import,nit #4 修复)
- `matchUserModelGrantsItem` → `modelGrants.ts` module-private(只在 modelGrants 内部用)
- `USER_MODEL_GRANTS_LIST_RE` / `USER_MODEL_GRANTS_ITEM_RE` 常量跟着对应 match 函数走
- `constantTimeEqual` → `metrics.ts`(只在 metrics auth 用)

### 3.3 跨资源,实施期决定(grep 后)
- `serializeContainer` — `adminComputeHosts.ts` 也用,`containers.ts` 也用 → 候选位置: 留在 `containers.ts` export,`adminComputeHosts.ts` 改 import 路径(blocker #2 修复)
- `parseUserFunnelFilters` — `users.ts` + `export.ts`(CSV 用相同 filters) → 候选: `users.ts` export 给 `export.ts` import,或 `_shared.ts`。实施期 grep 决定。

### 3.4 不进 _shared.ts 的红线
- 任何 domain 类型(User/Account/Order)不能渗入 `_shared.ts`,否则破坏单一职责
- 不为"未来可能复用"预留 helper

## 4. Hard gate(每条 fail 即 block)

### 4.1 Route inventory test(新增)
**比对维度**(blocker 强化): `method` + `path` + `pathPrefix` + 数组 **顺序** + `handler.name`

实现: 启动 router → 序列化 routes → JSON snapshot 对比基线。

**routes 当前不可达**(nit #3): `routes` 是 `createCommercialHandler` 内 line 396 的局部 const。需要新增 test-only 出口:
- 选项 A: 给 `createCommercialHandler` 加可选返回字段 `{ handler, _routesForTest? }`
- 选项 B: 抽 `buildAdminRoutesInventory()` 函数(纯函数,只构造 admin routes 子集),测试直接调
- **决策**: 选项 B(更窄面、不影响 prod 类型签名),实施期落地

**Baseline 路径**: `packages/commercial/src/__tests__/router-admin-baseline.json`(nit #2 修复)
