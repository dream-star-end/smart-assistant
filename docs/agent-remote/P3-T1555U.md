# P3 native transport infrastructure — in progress

AGENT-REMOTE-T1555U. This draft implements infrastructure; it does not yet run a
production Worker, remote ToolHost or authenticated relay. No production caller
or activation change is present. P2 was merged as #1342 / 9826fe951.

The distinct native protocol checks scoped frames, directions, immutable operation
hashes, typed callbacks, artifacts and Writer delivery ACKs. Native journal rows
share the existing principal transaction/fences with the legacy file/process
journal, in a separate normalized table. Global DB format v2 deliberately rejects
existing v1 databases; it does not upgrade an already-open v1 writer. Principal
metadata remains explicitly v1. Final execution receipts seal their event prefix;
Writer artifact/transcript delivery is a separate ACK. Unknown observations cannot
occupy the immutable final receipt. Unacknowledged delivery blocks rebinding and
checkpoint publication.

Tool session state uses the real root store/reducers and bounded native file cache.
A producer independently drains real runTools; a lost progress consumer only
detaches. Complete validation/permission/hook/call/post-hook promises are tracked,
with a separate canonical-call guard. Disposal retains listeners until foreground,
registered background handlers and resources drain; it does not assert physical OS
process-tree exit.

## Native artifact durability and the actual Writer (increment)

`nativeToolArtifactPathAllowed` is shared by wire artifacts and checkpoints. It covers safe ordinary text/JSON spill IDs, MCP text/binary/resource output, WebFetch binary output, and nested PDF JPEG pages. Host ingress cannot write native main/sidechain transcripts or metadata. Tool-use IDs are separate opaque provider identity, including long Google replay signatures; the 8 MiB frame budget still applies and infrastructure IDs keep their stricter shape.

The streaming installer runs inside `withSessionFile`'s tracked mutation with an opaque process-local lease and the actual session UUID flock. It checks content size/hash, fsyncs a private stage on the native volume, installs without overwrite, verifies installed bytes, and syncs each visited directory and parent, including existing directories on retry. A crash between linking target and unlinking the operation's stage is recovered only after matching the same inode. Canonical cwd aliases require the actual locked transcript inode; a copied transcript is rejected.

Explicit `appendEntryToFile` dependencies and ordinary main/sidechain recorders carry typed immutable dependencies through the real Project queue into the JSONL patch. Artifact failure prevents the reference append. Dependencies filtered out or removed by UUID dedup fail explicitly. Queue admission and the installer hash are not a delivery ACK. The later actual-delivery increment below supplies durable prepared/commit records, append-before-ACK reconciliation, and identical ACK resend.

Validation at this increment: 20 Node tests pass, including two real installer SIGKILL boundaries recovered by fresh Writer processes, existing PDF-directory parent-fsync EIO/retry, a 9 MiB streamed file, scope/lock/path/content/alias negatives and reentrant dependency rejection. The actual CCB writer suite passes 27 tests, including its existing file/queue cases and new main/sidechain dependency, conflict, failure and filtered/dedup negatives. Native protocol passes 12 tests including long/Unicode provider IDs and invalid/frame-budget negatives. These are synthetic local tests and no new real model call. This is a foundation increment, with no production bridge caller or P3 activation.

## Actual delivery and fresh recovery boundary (library increment)

The real Writer now prepares immutable UUID/time/content projections, installs and
reads back native artifacts, scans actual main/sidechain JSONL prefixes and parent
anchors, appends only a missing suffix through the original `insertMessageChain`,
and holds the transcript group locks through the control commit. The first proof,
original ACK, terminal state and delivery watermark commit atomically. This does
not rerun tools/hooks. Ambient workflow/nested targets and full Host source/blob
ownership remain activation blockers.

A logical session pins one native UUID. Control format 5 and checkpoint format 3
require explicit delivery/checkpoint watermarks and Writer generations; old formats
are rejected read-only before opening a writable WAL connection. Delivery count
covers Host commits only. `beginNativeWriter` must run before recorder/model
bootstrap, and normal admission/grant/start require its active generation. Normal
checkpoint publication never seals that generation, so model-only writes cannot be
mistaken for a quiescent migration merely because delivery D equals checkpoint C.

`NativeRecoveryService` is a supervisor-only, native-only library. Its constructor
captures an authenticated peer instance/connection/challenge and an optional
trusted handoff port. After the old execution lease expires or is released, claim
uses an independent generation CAS and preserves every original request/claim and
ledger producer. Pending permits, including expired pending permits, block normal
execution and mutation paths. An identical Worker registration can extend its TTL.
A claim refuses same-session unresolved legacy operations: this library has no
legacy evidence recovery endpoint and must not strand them behind its gate.

Recovery only replays authenticated ledger evidence and prepares/commits delivery;
it has no tool/model execution or new grant method. Completion requires a trusted
constructor-held port to stop all old writers/descendants, block new starts, acquire
the actual UUID and all transcript group locks, recover integrity intents, capture
before copying, and keep the locks through the control commit. Missing port rejects
completion. Request JSON cannot supply an exit claim or select that port. Both
capture and commit recheck callback scope and a synchronous lock capability inside
the transaction; delayed asynchronous store callbacks cannot publish after port
return. A normal execution-lease capture cannot seal recovery. Checkpoint pointer,
C, sealed Writer generation and completed permit publish in one transaction.

The production supervisor, process/exec ownership, full group-intent handoff port,
network authentication and actual Worker bootstrap caller are still absent. Tests
separate synthetic protocol/control ports from a single controlled writer process
with real UUID flock, files and SQLite. The latter waits the exact ChildProcess,
checks refusal while it holds the lock, injects before/after commit failures, replays
the original checkpoint after SIGKILL and restores a model-only append into a fresh
root. It is not evidence that a product supervisor has drained arbitrary descendants.

Validation for this increment: 46 targeted control/store/service tests pass; the
completed-permit read-only ACK retry change additionally passes all 10 recovery
tests. The full checkpoint suite (10) and original control service suite pass.
The actual CCB Writer's default CI wrapper passes its full inner suite under the
existing 150/180-second budgets. Gateway/references typecheck and scoped Biome pass.
There are no new real model calls, user-container operations or production changes.

## First actual runtime-service composition increment

`GatewayRuntimeServices` currently contains catalog and rolling turn-lease services.
Both production Gateway factories select the services and pass them through
GatewayDeps, SessionManager, engine construction and the actual CCB runner. The
local default remains a lazy wrapper around the existing singleton and renewal
client, preserving cache/identity initialization timing. This is a first pair of
services, not a complete or enabled Worker role. Models/SSE, durable persistence,
execution content and interactive Box still need their full ports. The independent
Worker entry must establish its private paths and public launch configuration
before importing the existing runtime; this increment does not make the old
credential-bearing Gateway entry safe to launch as a Worker.

A trusted explicit `ModelCatalogTransport` receives only catalog paths and an
abort signal. Selecting it skips container endpoint/bearer resolution. Cache,
singleflight, alias/security/availability checks and LKG semantics remain in the
original client. The client enforces its own deadline across both getting a
response and each body read, including transports that ignore abort; late success
cannot populate the cache. The 512 KiB body bound remains. Stuck iterator cleanup
cannot prevent deadline rejection.

The same service now supplies local turn decisions, advisor freezing/execution,
reviewer/panel selection, taskboard model checks and stage preflight, and prompt
catalog peeks. Auto-retry and rolling renewal share the injected renew function.
Credit guards and session/delegate price backfill use the same catalog; agent
multipliers retain their original independent 60-second refresh entry. Existing
billing policy and multiplier-composition decisions are unchanged.
