# P2: durable control state and quiescent native checkpoints

Task AGENT-REMOTE-T1555U; selfhost only. 面板登记由管家 TRACKER 代替（t1555u）。

This adds a real SQLite implementation of the P1 store and Linux native-session
checkpoint primitives. It is default OFF, has no production caller, does not move
the CCB query loop or execute a remote tool, and is not the P3 cutover.

## Decisions

Use the existing better-sqlite3 dependency, WAL and synchronous FULL on a private
persistent local volume. The personal edition currently has one control node;
Temporal/DBOS would add a second workflow authority without replacing the existing
dispatch/tape authority. Keep the store interface for a later distributed backend.

BEGIN IMMEDIATE serializes binding/lease fences, epoch watermark, operation journal
and event commits. Commit resolves only after SQLite commits; restart retains the
original operation key and dispatched intent. Metadata and operations are normalized,
so completed history does not count against the active reference capacity on every
request. A selected operation includes all unresolved records and historical source
job dependencies. Hashes/version/owner checks detect accidental corruption; they
are not signatures or substitutes for the private trusted storage boundary.

Queued cancellation/expiry can atomically finish only accepted work for which no
start grant exists. The not-started receipt is rejected as evidence from a worker
that has already started. A committed dispatch with no trustworthy receipt becomes
unknown after recovery and is never automatically replayed. **Unknown reconciliation
and consumption of real execution-side evidence belong to P3.** There is no force
unlock, JSON claim of quiescence, or exactly-once promise here.

Retain terminal records at least 30 days. The read-only paged retention proposal
excludes unresolved records, terminal sources referenced by unresolved job queries,
and all sessions with a checkpoint (conservative pinning). It never deletes rows.
Large terminal payloads are scanned one at a time. The event/row bounds remain
explicit; this is not an unlimited process-output archive.

## Native state ownership and restore

Use the existing CCB native ID and projects volume, not a copied HOME. The trusted
supervisor must provide one shared stateRoot/lock namespace for the native volume,
keep directory/inode replacement unavailable to the Worker, and grant the actual
Writer read access to its precreated lock. Lock files are never unlinked or GCed.
Every alias of the same native ID shares the same lock and restore marker.

writerCommand uses flock --no-fork and shell exec, so the actual CCB process owns
the kernel lock rather than its management parent. A new writer checks the durable
restore marker while holding that lock. Trusted checkpoint/restore tasks use
stateTaskCommand and must own the very same lock in their own PID; /proc/locks
checks the file identity and actual owner. The supervisor must stop every actual
native writer before checkpointing; a lease timeout is insufficient. This is a
local Linux lock, not a multi-host/NFS fencing claim.

A checkpoint copies only the selected session transcript and verified native
subtrees. Initial support is main JSONL; safe ordinary/labeled subagent IDs with
JSONL/meta.json; and toolu_* txt/json tool-results. Unknown layouts fail closed:
workflow subagents, MCP binary artifacts and PDF rendered page directories need
explicit P3 support before migration. No global resume-map, config, credentials,
settings, auth file, whole HOME, arbitrary JSON, symlink or restore temporary file
is copied. A native ID appearing in another project is rejected.

The checkpoint checks the committed native head supplied by the existing authority,
all source fingerprints and the complete selected file list, writes hashes/manifest,
fsyncs files and directory chains, then publishes the pointer while still holding
the lock. A crash before publication leaves no visible pointer; an unreferenced
sealed object may remain. Dispatch/turn/tape values are references, not a new
business authority; P3 supplies them from the existing committed owner.

Restore verifies the immutable object before touching native data. It persists a
marker first, refuses to overwrite different files, copies and fsyncs new files and
all new directory links, rehashes every target and rejects extra native files, then
commits and removes the marker. Interruption blocks all writers until the identical
restore completes. Only component-owned temporary files for listed targets may be
removed under this marker and lock; no broad cleanup or production GC is added.

## Verification

The targeted suite covers original protocol/service rules, DB restart, actual child
SIGKILL after dispatch commit, cross-process lease competition, terminal dependency
queries, queued cancellation/expiry, transaction rollback, corrupt/foreign DBs,
retention pins, real PID-held flock after management-parent SIGKILL, alias contention,
head mismatch/append/interruption, subtree restore, corruption and unsafe paths.
strace confirms new SQLite ancestor directories are fsynced before DB/WAL commits;
this is not a physical power-loss experiment.

Explicit offline probe at repository root:

```
TMPDIR="$PWD/.task-tmp" node_modules/.bin/tsx scripts/agent-remote/p2-native-resume.mts
```

The source CCB 2.8.4 CLI runs twice with a synthetic HOME/config/cwd, --bare and a
whitelisted child environment. Only a localhost fake Anthropic server is configured;
no OAuth, real key, user configuration or extra account pool is loaded. The -p flag
here is the API-source CCB offline fixture, not a cc subscription path. CLI itself
creates the JSONL; a locked checkpoint/fresh-directory restore is followed by a new
process resuming the same native ID. The fake checks first-turn user/assistant history
before responding. Removing the synthetic native files then makes resume fail without
another fake model request. Two localhost requests, zero real upstream calls.
