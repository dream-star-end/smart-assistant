# P1: remote agent / execution environment contract (experimental)

面板登记由管家 TRACKER 代替（t1555u）。Draft only; no merge/deploy.

P0 verified new CCB wrappers against an isolated execd container. It did not move
all native tools or select a production vendor. Per t1559u, real model TTFT remains
an explicit evidence gap (0/20 calls); the unrelated browser fixture CI race does
not block this draft and is steward-owned.

## Boundary and entry

`@openclaude/protocol/agentRemote` is a separate v1 subpath, never re-exported from
the main/browser entry. `gateway/src/agentRemote` has no production caller.
`createAgentRemoteService` returns undefined unless `OC_AGENT_REMOTE_ENABLED=1`,
before invoking the injected store factory. A volatile store additionally requires
`allowVolatileReference: true`. No flag was set in any existing service.

The service accepts a **trusted authenticated principal** from a future existing
control-plane handler, not an identity from user JSON. Wire validation alone is
not authentication. No credential, URL, Docker argv or vendor SSE event enters the
contract. There is no HTTP handler, daemon, timer, DB, model call or executor here.

## Registry and bindings

Worker identity = principal + workerId + workerInstanceId. A bounded TTL is checked
on every execution admission and observation. Engine names describe supported
agent engines, not account/model entitlement. Environment identity = principal +
environmentId + monotonic generation; it carries an existing supervisor's explicit
container incarnation/runtime/workspace/capability attestation. Container name
reuse cannot retain a generation. Same-generation metadata is immutable.

A session binding fixes both identities and a monotonic bindingRevision. Only the
approved binding is usable. Worker replacement, environment generation replacement
and rebinding reject unresolved operations, including unknown; no silent migration,
process killing or forced discard policy is supplied. Generation, revision and
lease epoch serve different purposes. They are not model securityEpoch/attemptNo.

`describeExistingContainer` validates/copies this explicit descriptor without
querying Docker or touching any user container. It does not attest capabilities.
A future adapter/supervisor must attest each one independently. The P0 execd adapter
has NOT proved file.cas, journal.durable, PTY, daemon restart recovery or arbitrary
process-tree stopping. Conditional writes/edits and tree stop reject absent those
capabilities. This draft does not wire the P0 wrapper to P1.

## Lease, journal and execution admission

An injected store transaction serializes the whole principal aggregate. Binding,
registry validity, lease owner/epoch/expiry and state CAS are checked together.
claim allocates the next safe integer epoch; renew/release compare the stored
claim; release never deletes the watermark. Caller-supplied high epochs cannot
advance it. TTL is at most five minutes and must be renewed explicitly. Time comes
from the authority's injected clock, not wire timestamps.

1. `accept` atomically journals a validated request, or returns an existing record.
2. `authorizeStart` atomically changes accepted -> dispatched **before sending any
   execution message**. Only one caller can get this transition. This is a durable
   dispatch intent in a future durable store, not proof the process has started.
3. The execution endpoint must independently fence and consume that intent at the
   point of execution, before any side effect. This requirement is NOT implemented
   by the reference service. An expired lease cannot stop an already running shell.
4. A validated started event changes dispatched -> started; ordered output follows.
   Cancel/deadline limit admission, not delayed started facts after dispatch.
   A terminal receipt changes started -> completed/failed/cancelled once.

The dedup key is principal/session/environmentId/generation/operationId. Epoch and
owner are excluded. A shared canonical JSON implementation plus SHA256 and domain
`agent-remote-operation-v1` hashes immutable protocol/binding/id/deadline/command.
Same key/hash returns the old record, even under a new epoch; changed semantics
reject. BindingRevision is in the hash, so an operation ID cannot be repurposed by
rebinding. Snapshots detach all input, stored state and returned records.

After lease loss, `recover` requires a newer claim. Accepted, never-dispatched work
can receive that claim; dispatched/started work becomes unknown. Unknown never
automatically reruns and blocks resource replacement/rebinding. A lost response,
timeout, EOF or HTTP 200 is not a receipt. Unknown reconciliation and retention/GC
policies require a later design; the reference has no deletion/force override.
Read-only `query` retrieves scoped journal history even after lease expiry.

## Events, receipts and cancellation

Events carry exact version, binding, operationId, payloadHash, lease token and
operation-local monotonic sequence starting at 1. Identical replay is idempotent;
same-sequence different content conflicts; gaps reject. Stale claims cannot append.
Output declares stream and UTF-8 byte offset; stdout/stderr advance separately.
Input strings are canonical-JSON checked before byte accounting. Output text is
bounded per event; this reference limits aggregate item counts, not production
retention or streaming throughput.

A completed process requires an exit code (7 is a completed nonzero execution).
Failed carries a stable error code. Cancelled requires explicit leader/process-tree
stop evidence; leader evidence never implies a whole tree stopped. Adapters remain
responsible for obtaining trustworthy evidence; schema validation cannot prove it.
`requestCancel` only records intent, does not mark stopped, kill a process or send a
command. It blocks a queued dispatch; started work may keep emitting output until
an actual terminal receipt. Queued cancel reconciliation is deliberately unresolved.
Terminal receipts are set-once; late contradictory completions reject.

Completed non-exec commands require a typed result matching the command kind.
File reads carry bounded UTF-8 content, byte offsets/size/eof, content hash and a
file version hash. Offsets/limits/hash and full-read version consistency are
validated; partial file version is the adapter's attestation. Non-EOF reads must
advance. An adapter must reject invalid UTF-8 boundaries or a limit too small for
the next whole character rather than return damaged/empty text. Binary/image
result transport remains a future extension, not implied by file.read v1.
Writes return path/size/hash consistent with submitted UTF-8; edits return final
hash/size plus previousSha256 and exactly one replacement. Actual atomic CAS still
requires an independently attested capability and executor implementation.

Exec started events expose a jobId/sourceOperationId saved in the journal before
completion. Status/logs/stop commands must reference that recorded exec job in the
same exact binding/generation; guessed or cross-operation jobs reject. Their typed
results repeat the scoped job; status includes state/exit code, logs include stream
and byte cursor/text, stop includes actual stop scope. Stop completed means observed
stop evidence, not mere submission; a pending stop cannot return completed. The
separate target exec record needs its own terminal receipt and is never rewritten
by a stop action's success. There is no real job query or execution implementation
here; those results remain future trusted adapter observations.

## Persistence and limits

`AgentRemoteStore.transact` requires atomic registry/binding/lease/journal/event
commit, detached snapshots, and durable commit-before-ack when durability='durable'.
Callbacks are synchronous/pure and must never execute commands. A real store must
preserve fences and dedup keys across crashes and implement multi-process CAS.
`VolatileAgentRemoteStore` is a single-isolate test/reference only: process death
loses all state. It cannot resume real jobs, provide a durable journal, or promise
exactly-once shell execution. No durable backend is selected or implemented.

## Validation

Targeted pure tests use node:test/tsx and fake authority time, without models,
containers, service changes or production DB access:

```
node_modules/.bin/tsx --test packages/protocol/src/agentRemote.test.ts packages/gateway/src/agentRemote/service.test.ts
```

They exercise default-off factory, cross-principal/binding fencing, concurrent
claims, stale/forged epochs, input snapshots, cross-epoch dedup/conflicts, dispatch
intent uncertainty, event replay/gaps, UTF-8 byte cursors, cancellation evidence and
terminal consistency. These tests are contract evidence, not distributed runtime
fault-injection or complete tool migration evidence.
