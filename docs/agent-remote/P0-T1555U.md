验证链：CCB 2.8.4 的真实 runToolUse 调度器 → 仅复用原 Read/Write/Edit/Bash inputSchema 的新 wrapper → OpenSandbox execd → 自建一次性容器。原 builtins、hooks、技能、浏览器、MCP、cron 与启动探测的本地实现仍待后续改造。此变更没有把原生工具宣称为全面远端化。

## 运行边界

仅 t1555u 专属 worktree 可运行，需已经有个人版现有依赖与 Bun；默认未设置开关时退出 2，不创建资源：

```bash
OC_AGENT_REMOTE_P0=1 bash scripts/agent-remote-p0/run.sh
```

脚本固定任务容器名，不接管同名现存对象。CPU 1、内存/交换合计 768 MiB、PID 128、nobody、只读根、cap-drop ALL、no-new-privileges；使用专属 bridge 和 localhost 发布端口。测试目录为独立 tmpfs，无宿主 workspace/用户卷/Docker socket；使用本次随机测试认证值，绝不输出或继承用户凭据。Worker 的 HOME/配置/缓存/临时目录均在该 worktree，启动环境采用白名单，hooks 和隐式学习关闭。所有主要阶段及每次 dispatch 检查 8 GB 停手线。失败也只清理本次资源。

不要直接运行现有浏览器脚本：其中仍有硬编码 /tmp，单设 TMPDIR 不足以覆盖。

## 已验证的证据边界

- 同名路径下 Worker/容器各有不同 sentinel，无共享 workspace；实际读取远端标记，中文/emoji 写入与单匹配编辑由容器内独立 sha256sum 核对，Worker 陷阱文件不变。
- Bash 回执含 cwd、uid、PID namespace、stdout/stderr，非零退出 7 不被 HTTP 200/EOF 冒充成功；容器 namespace 与 Worker 宿主不同。
- 后台任务按原 job ID 查询、UTF-8 日志 byte cursor 续取、取消后查询终态，并独立检查记录的 leader PID 消失。只证明本次单进程任务，未证明所有后代进程清理。
- 执行端停止后 Read/Bash 经过真实调度器产出 is_error=true；wrapper call 数为 0，Worker 本地文件/命令未被触发。
- 37 次正向工具调度、2 次断线负测，0 真实模型调用。首次 4 个验证调用之外，每种工具取 8 个样本计算 RTT p50/p95。真实模型 TTFT 未测，不能用工具事件代替。
- 修复过两个验证错误：磁盘检查不能只做启动前一次；容器内检查必须 set -eu，避免失败被最后打印吞掉。修复后完整重跑，不将旧轮结果当最终证据。
